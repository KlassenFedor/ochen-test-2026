# Конструктор векторных иллюстраций: задача и решение

Дата объединения документов: 23 ноября 2026 года.

Документ объединяет требования из `Задача.pdf` и проект решения из `Архитектура-плагина-Figma.docx`. Сведения о фактическом устройстве Figma-файла получены при отдельной проверке через интеграцию Figma. Требования, планируемое решение и уже подтверждённое состояние ниже разделены явно.

## 1. Задача

Разработать инструмент, который автоматически собирает иллюстративные композиции разных форматов из готовых векторных объектов заказчика.

Нужны два сценария:

1. Пользователь вводит метафору или заголовок. Инструмент подбирает подходящие предметы и собирает композицию.
2. Пользователь перечисляет названия предметов. Инструмент размещает все указанные предметы в композиции.

Отдельный сайт не обязателен: задание разрешает реализовать решение как плагин Figma. Выбран этот вариант.

### Ограничения исходного задания

- Итоговая композиция состоит только из элементов исходных **20 иллюстраций**. Генерация новых предметов не допускается.
- Нужно сохранять векторную структуру, контуры и пропорции предметов. Предусмотренные заданием перемещения, повороты, масштабирование с сохранением пропорций и перекраска допустимы.
- AI-инструменты разрешены для разработки и анализа метафор. Их использование во время работы готового плагина не является обязательным.
- Результат экспортируется в редактируемый SVG, без превращения объектов в растровое изображение.
- Оцениваются качество решения и работающий результат, а не количество функций. Согласно заданию, тестовая работа не будет использоваться компанией в коммерческих целях.

### Обязательные возможности

| Область | Требование |
| --- | --- |
| Библиотека | Использовать заранее подготовленную библиотеку SVG-иллюстраций либо загружать её; сохранять структуру, исходные цвета и пропорции. В нашем решении используется подготовленная библиотека внутри демофайла Figma. |
| Сборка | Добавлять предметы на общий холст и объединять элементы нескольких исходных иллюстраций. |
| Редактирование | Перемещать, поворачивать, дублировать и удалять предметы, менять порядок слоёв. |
| Параметры | Давать выбор размера и цветовой схемы. |
| Палитра | Загружать пользовательскую палитру и автоматически перекрашивать композицию. Одного сохранения исходных цветов недостаточно. |
| Экспорт | Скачивать итоговую композицию в SVG с сохранением векторности и редактируемости. |

## 2. Выбранное решение

Локальный плагин Figma на TypeScript с простым HTML-интерфейсом и сборкой через esbuild. Все данные — каталог, словари тем, палитры и шаблоны — входят в готовую сборку.

Плагин работает с открытым документом через встроенный Figma Plugin API. Сервер, внешние ключи, REST API и модель для выполнения выбранных сценариев не требуются. Интеграция Figma, использованная при подготовке, нужна для инспекции файла и не является зависимостью готового плагина.

| Часть решения | Ответственность |
| --- | --- |
| Демофайл Figma | Предоставленный файл подтверждён пользователем как рабочая копия. Мастер-компоненты, фоны и область «Демо» готовятся в отдельных секциях существующей страницы библиотеки: тариф Starter не разрешает добавить страницы. |
| Панель плагина | Два режима ввода, выбор формата, детализации и палитры, импорт палитры, команды сборки, изменения роли предмета и экспорта. |
| Логика TypeScript | Каталог, нормализация названий, поиск по темам, расчёт раскладки и проверка палитр. Работает с обычными данными, отдельно от холста. |
| Адаптер Figma | Индексирование компонентов открытого файла, создание экземпляров, применение палитры, хранение метаданных сцены и экспорт. |
| Комплект передачи | Запускаемая сборка в ZIP, демофайл, репозиторий, ролик на 60–90 секунд и 2–3 экспортированных SVG. |

Ручные перемещения, повороты и изменение порядка слоёв выполняются штатными инструментами Figma. Отдельный редактор холста в панели не нужен.

Количество исходных иллюстраций, предметов и их вариантов учитывается отдельно.

## 4. Подготовка библиотеки и каталог

### Организация демофайла

Пользователь подтвердил, что файл по исходной ссылке уже является рабочей копией, и разрешил создавать и изменять в нём компоненты и слои. Повторное копирование не требуется. Существующие листы L/S сохраняем для сравнения; подготовленные мастера размещаем отдельно.

В архитектуре страница названа «Библиотека», фактическое имя — «Библиотека компонентов». Из-за ограничения Starter на новые страницы используем внутри неё секции «Библиотека · Компоненты» и «Демо · Плагин». Адаптер должен искать мастер-компоненты в первой секции, а новые композиции создавать во второй. Секции пока не созданы: подготовка через MCP остановлена лимитом вызовов.

### Единица переиспользования

Один предмет со всеми контурами, тенями и масками становится одним локальным мастер-компонентом. При подготовке сохраняются геометрия, исходные габариты и внутренние связи слоёв. Фоны с декоративными линиями оформляются отдельными компонентами из оригинала.

Для каждого предмета учитываются:

- идентификатор предмета, например `book`;
- уровень детализации: `large` / `small`, соответствующий L / S;
- роль: `main` / `background`;
- доступные варианты, их эталонные размеры и источник;
- привязки заливок и обводок к позициям палитры.

Примеры устойчивых ключей: `book/large/main`, `book/small/background`. Это схема именования, а не подтверждение наличия всех перечисленных вариантов.

Индекс компонентов строится при запуске по именам либо свойствам наборов вариантов. Постоянные ID узлов исходного файла в рабочий каталог не записываются: плагин должен работать на копии демофайла.

### Данные каталога

В `data/catalog.json` хранить ID предмета, русское название, синонимы и словоформы, теги тем, ссылку на источник по имени, ключи доступных вариантов и эталонные габариты. Например: `book` → «книга», «книгу», «книжка»; темы — чтение и учёба.

Перед сборкой адаптер загружает страницу библиотеки, строит индекс и проверяет все необходимые ключи. При дубликате, недостающем варианте или недоступном фоне панель сообщает конкретный проблемный ключ. Новый кадр создаётся после успешной проверки всего запроса.

## 5. Пользовательские сценарии и подбор предметов

Оба режима ввода возвращают одну структуру: упорядоченный список пар «ID предмета + роль». Повторения в явном списке обозначают отдельные экземпляры.

| Режим | Правило | Ожидаемый результат |
| --- | --- | --- |
| Названия | Разделить ввод по запятым, убрать лишние пробелы, привести к нижнему регистру, учитывать «ё/е», синонимы и словоформы. Проверить каждую позицию. | «Книга, телефон» сохраняет оба предмета. Неизвестное слово подсвечивается, пользователь получает доступные названия. |
| Заголовок или метафора | Сопоставлять целые слова и последовательности слов с локальным словарём. Длинные совпадения важнее коротких. При одинаковой длине приоритет у точной формы, затем у совпадения основы и группы родственных слов. При равенстве действует порядок каталога. | «Учиться в дороге» → книга и наушники. Первый предмет получает главную роль. Если совпадений нет, показать каталог и предложить уточнение. |

Для заголовка первоначально выбирается от одного до трёх предметов с положительной оценкой. При прямом вводе ни один распознанный предмет не теряется, даже если их больше, чем предусмотрено основным шаблоном.

Русский стеммер сближает словоформы, например «смартфон» и «смартфонами». Группы родственных слов покрывают приставки и чередования в заданных семействах, например «звонить» и «перезвонить», «собрать» и «собирать». Характерные ложные совпадения корректируются отдельным списком словоформ. Покрытие метафор задаёт локальный словарь тем. [Русский алгоритм Snowball](https://snowballstem.org/algorithms/russian/stemmer.html)

## 6. Форматы, масштаб и композиция

Архитектура предусматривает квадратный, горизонтальный и вертикальный кадры, два уровня детализации L/S и выбор главной либо фоновой роли предмета. В первой версии используются размеры 1080 × 1080, 1200 × 630 и 900 × 1200. Их и параметры шаблонов предстоит сверить с референсами в Figma. [Настройки форматов](../data/layouts.json)

### Шаблоны

Подготовить по примерам заказчика:

1. Один предмет с одним центром внимания.
2. Диагональную пару.
3. Наложение двух главных предметов.
4. Сцену с главным и фоновым объектами.

Для каждого формата хранить точки привязки в долях ширины и высоты, порядок слоёв и допустимое кадрирование. Начальное приближение для диагональной пары в квадрате — центры `(0,35; 0,65)` и `(0,65; 0,35)`, затем их нужно уточнить на реальных предметах.

### Правила размещения

- Детализация определяет исходные варианты предметов.
- Для всей композиции применяется единый коэффициент масштаба относительно эталонных габаритов, чтобы сохранить относительные размеры предметов.
- Предмет позиционируется относительно центра. При смене формата используются точки соответствующего шаблона.
- Подходящие шаблоны проверяются в заданном порядке. Учитываются видимая площадь главного предмета и перекрытие передними слоями.
- Намеренный заход за край допустим, если соответствует референсам.
- Команда «Другой вариант» перебирает допустимые раскладки.
- Для явного списка, превышающего вместимость шаблона, используется раскладка по рядам с промежутками и общим масштабом. В кадре остаются все запрошенные предметы.

## 7. Палитры и перекраска

Три цветовые схемы подтверждены в исходнике: сиреневая, персиковая и бирюзовая. У каждой две колонки по четыре позиции: фон и объекты. Точные RGB прочитаны из образцов; служебный плагин повторно читает их при запуске, сохраняя дробные значения каналов.

В монете и букете есть четыре дополнительных видимых оттенка вне основных восьми позиций. В фонах также есть белые детали и нейтральные краски скрытых слоёв. При подготовке они сохраняются как отдельные постоянные семантические переменные `detail/*`, чтобы не менять исходную иллюстрацию. Внешняя палитра из восьми цветов их не перекрашивает. Эти исключения нужно учитывать при проверке фоновых ролей.

Цвета фона разрешено использовать в главных предметах. Фон кадра и монохромные фоновые предметы используют фоновые оттенки. При смене роли подключается соответствующий подготовленный вариант предмета.

### Формат пользовательской палитры

Начальный формат — JSON с версией, названием и именованными массивами цветов:

```json
{
  "version": 1,
  "name": "Пример",
  "background": ["#D8CEF5", "#AB96ED", "#7562C0", "#191919"],
  "object": ["#FAE9A9", "#F5A4AD", "#FDE4E2", "#FFFFFF"]
}
```

Значения в примере демонстрационные. Структура из двух колонок по четыре позиции подтверждена в Figma, но реальные цвета отличаются от примера. В каталоге подготовки сохраняются и HEX для пользовательского JSON, и исходные дробные RGB для точного воспроизведения мастеров. На Starter три палитры хранятся в трёх отдельных коллекциях с одним режимом; перекраска использует соответствующие переменные без платных режимов.

### Привязка к слоям

Каждому окрашиваемому каналу слоя — заливке или обводке — назначается позиция, например `background[1]`. Если локальные цветовые стили уже однозначно выражают назначение, использовать их имена. Для остальных каналов хранить явную привязку по пути слоя и индексу краски. Одинаковые RGB с разными назначениями нельзя считать одной позицией автоматически.

До изменения сцены проверяются версия, число цветов, формат `#RRGGBB` и наличие всех необходимых привязок. Затем меняется RGB соответствующих красок с сохранением прозрачности.

При повторной перекраске позиции берутся из разметки мастера, а не угадываются по текущему цвету экземпляра. При ошибке проверки панель указывает конкретную позицию, действующая палитра сохраняется.

## 8. Сцена, ручные правки и команды

На фрейме сцены через `sharedPluginData` хранить версию схемы, формат, детализацию, палитру с её цветами и идентификатор шаблона. На каждом размещённом предмете — ID каталога и роль. Повторные экземпляры одного предмета остаются отдельными узлами Figma.

Текущие позиции, углы и порядок слоёв читать с холста. Это позволяет после закрытия панели продолжать работу с той же сценой, включая предметы, которые дизайнер передвинул, продублировал или удалил вручную.

| Команда | Поведение |
| --- | --- |
| Собрать / другой вариант | Создать новый фрейм рядом с предыдущим и выделить его. Ранее отредактированная композиция сохраняется. |
| Добавить предмет | Добавить экземпляр в выбранную сцену и применить палитру сцены. |
| Сменить роль | Заменить вариант предмета, сохранив центр, угол, общий масштаб и место в порядке слоёв; применить палитру сцены. |
| Применить палитру | Обновить сцену на месте. Штатная палитра меняет и вариант фонового декора. Пользовательская обновляет цвета текущего фона. |
| Экспортировать | Выгрузить выбранный фрейм с его текущим содержимым и правками. |

При сбое новой сборки удаляется временный недостроенный фрейм. Явный список и добавление ограничены 24 предметами. Старые кадры с частными метаданными нужно [подготовить к передаче](../README.md#передача-редактируемых-кадров) из установки с исходным ID.

## 9. Экспорт SVG

Архитектура предлагает экспорт выбранного фрейма через `exportAsync({ format: "SVG", svgIdAttribute: true })` с передачей байтов панели для скачивания.

Проверка результата проводится повторным импортом SVG в Figma:

- внутри каждого предмета можно выделить отдельный векторный контур;
- сохраняются контуры, относительные размеры, маски и кадрирование;
- в SVG отсутствуют растровые вставки `<image>`;
- результат соответствует текущему положению и порядку предметов на холсте.

Сохранение теней, масок и полной векторности нельзя считать подтверждённым только по наличию узлов `VECTOR`. Это нужно проверить на реальном экспорте. Если исходный эффект приводит к растрированию, способ его сохранения необходимо решить на первом прототипе до заполнения всей библиотеки.

## 10. Предлагаемая структура проекта

```text
manifest.json
package.json
src/
  main.ts
  ui.html
  catalog.ts
  layout.ts
  palette.ts
data/
  catalog.json
  themes.json
  palettes.json
  layouts.json
dist/
```

Основной конструктор реализован в `src/`. Адаптер находится в `src/figma/`, код взаимодействия с панелью в `src/ui.ts`. Сборка, тесты и запуск описаны в [README](../README.md). Подготовка библиотеки встроена в конструктор и реализована в `src/figma/prepare-library.js`. План сопоставления с оригиналом находится в `tools/prepare-library/library-plan.json`.

| Файл или каталог | Назначение |
| --- | --- |
| `manifest.json` | Манифест с путями к собранным `main` и `ui`, типом редактора `figma`, `documentAccess: "dynamic-page"` и `networkAccess.allowedDomains: ["none"]`. |
| `package.json` | Зависимости и команды сборки TypeScript/HTML через esbuild. |
| `src/main.ts` | Входная точка, обработчики команд, работа с узлами и адаптер Figma. |
| `src/ui.html` | Панель, локальное чтение файла палитры, скачивание SVG. Обмен с основным кодом — типизированными сообщениями. |
| `src/catalog.ts` | Поиск по названиям и темам, работа с каталогом. |
| `src/layout.ts` | Выбор шаблона и расчёт размещения. |
| `src/palette.ts` | Проверка структуры палитры и правил назначения цветов. |
| `data/` | Каталог, темы, палитры и шаблоны, подключаемые на этапе сборки. |
| `dist/` | Готовые файлы, на которые ссылается манифест; комплект должен запускаться без локальной пересборки. |

Чистую логику поиска, раскладки и проверки палитр проверять отдельно от Figma. Векторность, сохранение ручных правок и работу на копии проверять на холсте и экспортированных SVG.

## 11. Порядок разработки

### Этап 1. Подготовка и проверка основного риска

1. Использовать предоставленную рабочую копию; подготовить секции библиотеки и «Демо» на существующей странице.
2. Взять книгу и телефон из L, оформить локальные мастер-компоненты, сохранить исходную геометрию и задать устойчивые ключи.
3. Создать минимальный плагин: загрузить страницу библиотеки через `loadAsync()`, найти компоненты и создать экземпляры через `createInstance()`.
4. По вводу «книга, телефон» собрать квадратный кадр с телефоном поверх книги.
5. Передвинуть телефон штатными средствами Figma, сменить палитру.
6. Экспортировать SVG, повторно импортировать и проверить контуры обоих предметов, относительные размеры, маски и тени.

Переход к массовой разметке библиотеки — после успешной проверки этого сценария.

### Этап 2. Полный сценарий прямого ввода

Подключить квадратный, горизонтальный и вертикальный кадры, оба уровня детализации и шаблоны. Уточнить числовые размеры и точки размещения по примерам заказчика. Сверить одну композицию во всех форматах. Затем провести полную инвентаризацию исходников и заполнить каталог, явно отметив недоступные варианты.

### Этап 3. Цвет и роли

Снять три штатные схемы с оригинала, закончить разметку заливок и обводок, подключить импорт JSON и смену роли. Проверить повторную перекраску после перемещения и дублирования. Дефектная палитра должна отклоняться до изменения кадра.

### Этап 4. Подбор по заголовку

Разметить темы, фразы и синонимы. Проверить демонстрационный заголовок, новую перефразировку и ввод вне словаря. Оба режима используют один механизм сборки и один экспортёр.

### Этап 5. Передача результата

Проверить установку из ZIP на свежей копии демофайла, подготовить 2–3 SVG и записать ролик. Добавить инструкцию запуска и описание архитектуры в репозиторий.

## 12. Приёмка

| Проверка | Критерий |
| --- | --- |
| Запуск | В Figma Desktop открывается демофайл; `manifest.json` импортируется из распакованного ZIP; сборка, внешние ключи и доступ к оригиналу заказчика не требуются. |
| Прямой ввод | «Книга, телефон» создаёт оба предмета; повторы сохраняются; неизвестное название даёт подсказку. |
| Подбор по смыслу | Знакомый по смыслу новый заголовок подбирает уместные предметы; отсутствие совпадений обрабатывается явно. |
| Форматы и детализация | Одна сцена проверена в квадрате, горизонтали и вертикали; используются соответствующие исходники L/S. |
| Роли | При смене роли выбирается подготовленный вариант; монохромный предмет следует правилам фоновой палитры. |
| Смешанная композиция | Можно добавить предмет из другой исходной иллюстрации. |
| Ручные правки | Поворот, перемещение, дублирование, удаление и порядок слоёв сохраняются при смене схемы и импорте четвёртой палитры. |
| Невалидная палитра | Ошибка названа, существующая сцена не меняется. |
| SVG | Экспорт учитывает текущие правки; повторный импорт сохраняет редактируемые контуры, маски и кадрирование; растровых `<image>` нет. |
| Переносимость | Индекс строится по устойчивым ключам; работа не зависит от ID оригинального файла. |

### Демонстрация на 90 секунд

| Время | Действие |
| --- | --- |
| 0–25 с | Ввести «Учиться в дороге», собрать сцену с книгой и наушниками; показать этот набор в горизонтальном кадре. |
| 25–50 с | Переключиться на названия, ввести «книга, телефон»; передвинуть телефон поверх книги и сменить роль книги на фоновую. |
| 50–70 с | Импортировать новую палитру; показать перекраску фона, заливок и обводок с сохранением положения телефона. |
| 70–90 с | Скачать SVG, импортировать его обратно в Figma, раскрыть группу и выделить отдельную векторную деталь. |

### Что передать проверяющему

Одна ссылка на репозиторий. В начале README разместить ролик, ссылку на ZIP готового плагина, копию демофайла и инструкцию запуска. Приложить 2–3 готовые композиции в SVG, описание хранения, извлечения и переиспользования элементов и список фактически использованных AI-инструментов.

## 13. Состояние реализации

Первая версия конструктора собрана. Автоматические проверки охватывают подбор предметов, раскладку, палитры, хранение сцены, смену роли и обработку SVG на модели документа. Для проверки реального холста есть [отдельный сценарий](Визуальная-проверка.md).

Подготовка исходников и проверка в Figma Desktop предстоят:

| Что осталось | Когда закрыть |
| --- | --- |
| Выполнить подготовку в предоставленной рабочей копии. Пользователь разрешил изменения; интеграция достигла лимита MCP на Starter до создания компонентов. | После возобновления доступа MCP либо запуском служебного плагина в Figma Desktop. |
| Оформить книгу и телефон как компоненты, задать ключи и привязки цветов. | Первый этап разработки. |
| Проверить SVG после экспорта и повторного импорта. | До массовой подготовки библиотеки. |
| Инвентаризация 10 предметов × L/S × две роли и 6 фонов выполнена. Перенести их в компоненты и проверить сохранность габаритов. | При запуске подготовки библиотеки. |
| Реальные палитры прочитаны; применить подготовленные привязки и проверить постоянные дополнительные оттенки. | При запуске подготовки библиотеки и проверке цвета. |
| Сверить размеры кадров и шаблоны с референсами, оценить подбор по реальным заголовкам. | При проверке первой версии. |
| Проверить запуск локального плагина в Figma Desktop. | После загрузки двух development-плагинов и подготовки библиотеки. |

Эти пункты входят в разработку. Подготовка библиотеки с проверкой геометрии, цветов и SVG [доступна в окне конструктора](../tools/prepare-library/README.md). В демофайле библиотека уже подготовлена.
