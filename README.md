# Конструктор иллюстраций для Figma

Плагин собирает редактируемые композиции из десяти исходных предметов. Он подбирает предметы по заголовку или берёт их из списка, использует варианты L и S и сохраняет результат в SVG. Плагин работает в Figma Desktop через встроенный Plugin API. Сервер и MCP для запуска не нужны.

## Первый запуск

1. Распакуйте архив и откройте [демофайл задания](https://www.figma.com/design/OQnymDXpbDHoABKg8ks9R7/?node-id=26-11438) в Figma Desktop с доступом **Can edit**.
2. В меню **Plugins → Development → Import plugin from manifest** выберите `manifest.json` из распакованной папки. Запустите **«Конструктор иллюстраций»** в том же меню.
3. Введите `Книга, телефон` и нажмите **«Создать композицию»**.

Архив содержит один готовый плагин. Шаблон проекта, Node.js и перенос ID для проверки не нужны. В демофайле уже есть библиотека. Если открыт файл задания только с исходными слоями, нажмите **«Подготовить библиотеку»** в окне конструктора. [Импорт локального плагина в Figma](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development)

Автономная сборка содержит мастера и палитры. Её можно запустить в новом пустом файле Figma. Нажмите **«Создать композицию»**, чтобы автоматически установить библиотеки и собрать первый кадр. Следующие композиции используют уже установленные мастера.

На вкладке «Редактирование» выделите кадр или предмет внутри него. В блоке «Цвета композиции» выберите готовую палитру или загрузите свою из JSON, затем нажмите «Перекрасить кадр». При создании новая композиция использует палитру со своей вкладки. Для смены роли выделите один предмет. Быстрый старт, примеры и частые вопросы доступны по кнопке «Помощь и инструкции» в панели.

## Передача редактируемых кадров

Новые кадры доступны в том же Figma-файле или его полной копии из установки, импортированной напрямую из ZIP. Для кадров, собранных старой версией, сначала обновите папку `dist/` у автора, сохранив его исходный `id` в манифесте. Выделите каждый старый кадр и нажмите **«Подготовить старый кадр к передаче»** во вкладке «Редактирование». После этого передайте файл с библиотекой. Прежний ID нужен для чтения старых метаданных во время переноса. [Общие метаданные Figma](https://developers.figma.com/docs/plugins/api/properties/nodes-setsharedplugindata/)

## Разработка

```sh
npm ci
npm test
npm run build
npm run package
```

`npm test` проверяет TypeScript, чистую логику, поведение адаптера на модели документа и правила подготовки библиотеки. Для проверки реальных узлов, цветов и экспорта используйте отдельный сценарий. [Визуальная проверка](docs/Визуальная-проверка.md)

`npm run package` использует стандартный модуль `zipfile` из Python 3 и сохраняет архив в `artifacts/illustration-composer.zip`. Имена файлов с кириллицей помечаются как UTF-8. Для миграции частных метаданных в своей старой установке можно отдельно собрать архив командой `npm run package -- --plugin-id ИСХОДНЫЙ_ID`.

Для сборки автономного ZIP в готовом демофайле откройте **«Помощь и инструкции» → «Выгрузка мастеров» → «Выгрузить библиотеку»**, скачайте `portable-library.json` и сохраните его в `data/`. Выполните `npm run package -- --portable`. Ключ проверяет наличие выгрузки перед упаковкой.

Мастера индексируются по именам наборов и вариантам `Size`, `Role` и `Scheme`. Настройки кадра хранятся в `sharedPluginData`, а позиции и порядок предметов берутся с холста. Явный список и добавление ограничены 24 предметами на кадр. При выборе штатной палитры обновляются цвета и фоновый мастер. Пользовательская палитра обновляет цвета текущего фона.

Размеры кадров 1080 × 1080, 1200 × 630 и 900 × 1200 выбраны для первой версии. Размеры и точки привязки можно уточнить после просмотра реальных композиций. [Настройки форматов](data/layouts.json)
